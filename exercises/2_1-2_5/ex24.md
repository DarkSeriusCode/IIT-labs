# Упражнение 2.24

Давайте перепишем `Dockerfile` в фронтенде и бекенде, убрав переменные среды в `docker-compose.yaml`,
чтобы не пересобирать образы при любом малейшем изменении, а просто редактировать поведение контейнера
через `docker-compose.yaml`

`Dockerfile` для фронтенда:
```Dockerfile
FROM node:16.0

EXPOSE 5000

WORKDIR /usr/src/app

COPY . .

ARG REACT_APP_BACKEND_URL
RUN npm install
RUN npm install -g serve

RUN npm run build

CMD ["serve", "-s", "-l", "5000", "build"]
```
Здесь мы используем `ARGS`, т.к в силу того как работает React, `ENV` не будет работать, ведь `ENV`
задаёт переменные среды не при сборке приложения, а при работе, а вот `ARG` можно задать через 
`docker compose` и это уже переменные среды при сборке.

Однако при каждом изменении `REACT_APP_BACKEND_URL` нужно пересобирать образ фронтенда

`Dockerfile` для бекенда
```Dockerfile
FROM golang:1.16.15

EXPOSE 8080

ENV PORT=8080

WORKDIR /usr/src/app

COPY . .

RUN go build

CMD ["./server"]
```

Сам `docker-compose.yaml`
```yaml
services:
  frontend:
    image: rustykrabik/frontend
    build:
      context: example-frontend
      args:
        REACT_APP_BACKEND_URL: http://localhost:8080
    ports:
      - 5000:5000

  backend:
    image: rustykrabik/backend
    build: example-backend
    environment:
      - REQUEST_ORIGIN=http://localhost:5000
    ports:
      - 8080:8080
```

Теперь добавим конфигурацию для запуска `Redis`, который будет запускаться отдельным контейнером.
```Dockerfile
  redis:
    image: redis:8
```

Открыв страницу `http://localhost:5000` и нажав на кнопку упражнения 2.4 мы увидим, что всё работает
